# 基于 Semantica 的高数复习与多应用知识管理平台

> 历史报告草稿，部分功能描述、样本数量和部署状态属于早期阶段。当前实现以 [项目 README](../README.md)、[使用说明](usage.md) 和验证记录中的后续条目为准。

> 项目报告草稿。实现与功能验证部分依据当前代码和实际部署；研究实验尚未完成，本文不提供虚构的质量指标。

## 1. 选题与目标

本项目对应“期末复习助手”选题，围绕高等数学资料构建学习平台。管理员导入和校对教材、维护知识关系与题目，创建绑定不同知识库的学习应用；学生通过应用开展有出处的问答、自测和错题复习。

高数资料包含公式、定理条件和概念之间的严格区别，单纯使用文本相似度容易忽略适用条件。例如“可导”与“连续”相关，但不能作为同一概念合并。项目将知识编辑、图关系和数学工具结合，重点解决资料可追溯、应用范围隔离及不确定结果处理问题。

## 2. 系统设计

前端采用 Vue 3、TypeScript 和 Element Plus，使用 KaTeX 展示公式、ECharts 展示关系与掌握程度。后端采用 FastAPI、SQLAlchemy 和 Alembic，PostgreSQL 保存业务数据及知识发布快照，pgvector 保存向量，Celery 与 Redis 处理后台任务。系统使用 Podman 部署，原文件与数据库存放在独立持久化卷中。

Semantica 0.7.0 用于 ContextGraph 图谱构建与遍历、实体重复候选、来源追踪及版本快照。早期逐页 PDF 解析也使用 Semantica；当前 PDF/图片按用户要求统一使用 PaddleOCR，再通过统一分发器执行规则或模型语义切分。账号、应用配置、内容与业务发布状态由平台维护；数学计算和限定题型判分由 SymPy 完成。

生成模型和 Embedding 模型按应用分别配置。知识库的抽取模型独立配置。同一知识发布版本可以拥有多个 Embedding 索引；索引按提供方、地址、模型和维度生成签名，避免不同向量空间混用。本地模式不会在失败时自动切换云端。

## 3. 核心方法

### 3.1 知识质量与发布

导入保留原文件及稳定来源位置。PDF 使用页号，DOCX 使用段落定位。按用户最新要求，人工审核与模型审核步骤已移除；知识、关系、题目保存后可直接发布。发布保留来源归属、引用完整性、前置关系无环、向量空间一致性等程序校验；缺少人工维护的适用条件元数据不再阻止发布。

草稿修改与发布版本分离。发布过程中生成知识快照及所需索引，成功后切换当前版本；失败时继续使用旧版本。应用切换 Embedding 与知识库发布协调锁定，避免生成模型配置与可用索引不一致。撤回内容立即从新请求的有效知识范围移除。

### 3.2 有范围约束的图检索

请求仅指定应用，后端读取已发布应用绑定的知识库。普通知识问答融合 BM25 与向量候选，沿发布版本中的有效关系最多扩展两跳，选择最多 8 个知识单元。查询时把文件名、文档版本和来源位置关联到片段，既用于词法检索，也提供给生成模型。

涉及明确资料名称、年份和考试类型时，先定位文档，再在其有效发布片段内搜索；候选文档有歧义时追问。文档概览优先收集正文，排除纯标题、页码与考生信息，最多选择 32 个单元、24,000 个正文字符，长文按章节或页面分配覆盖并标记不完整。试卷与答案按问题意图选择。文档范围扩展无需新增语义关系，不重新解析资料或修改旧向量。图谱、题库、来源与会话接口继续执行服务端范围和用户校验。

生成回答需要返回合法引用，程序检查引用标识及版本。回答生成期间资料被撤回或版本改变时，要求重新请求。程序检查能保证引用指向存在的有效来源；引用是否支持回答结论仍需人工评测。

### 3.3 数学验证

数学输入通过受限表达式树构造 SymPy 对象，不直接执行输入字符串。计算在独立限时进程中运行，首版支持一元函数极限、求导、积分以及限定答案等价检查。

判分区分正确、错误和待核对。定义域不同、符号系统无法确定或计算超时时，不直接判错；证明题仅提供参考。特别保留约分前的定义域，防止把在零点无定义的 `x/x` 当作在整个实数域上等价于 `1`。不定积分检查积分常数。

### 3.4 复习优先级与推荐

重要性融合去重后的资料覆盖频次、PageRank 和往年题频次，初始权重分别为 0.3、0.3、0.4；无往年题时前两项各为 0.5。

知识点掌握程度使用最近 20 次有效作答的平滑正确率，无作答时标记尚未评估。复习推荐按薄弱程度与重要性加权，并在目标知识之前安排薄弱的前置知识。页面展示推荐原因和各项依据。上述数值是初始设定，效果尚需实验验证。

## 4. 当前数据与功能验证

用户提供了 17 份资料。初次按文字层导入得到 611 条原文片段；随后按用户确认清空全部旧知识，使用 PaddleOCR 重新识别 16 份 PDF 的 561 页，并在本地解析 1 份纯文字 DOCX。上一轮得到 9,481 条待审核内容（1,547 条独立公式），9,992 张来源图片完整。文档与页号核验记录于 artifacts/reimport-summary.json；这些 OCR 输出不能计作已正确抽取并审核的高数知识。按用户后续要求，这批旧条目已删除，保留原文件和 OCR，重新通过 ds-flash 进行语义切分与知识类型标注；本轮生成 1,685 条语义条目，包含 318 条跨页整合，原文字符及来源完整性核验通过；完整结果见 artifacts/semantic-reimport-summary.json。分组正文保持原文，实体关系三元组仍需另外提取和审核。

已对 `Ch1-2.pdf` 前 30 页使用 Semantica 实际解析，保存页号和文本结果。资料检查发现部分公式存在编码或排版损失，因此必须对照原文审核，文本提取成功不能等同于公式正确。

现有 1,685 条语义知识随后全部通过 ds-flash 执行图文或原文段落审核，最终通过 1,309 条、需修改 318 条、无法判断 58 条，调用失败为 0。审核保存模型、知识修订号、逐项检查和来源证据，并验证正文未被自动改写；这一历史审核阶段现已停用，结果不再限制内容使用；这些模型结论不作为人工准确率评分。结果见 `artifacts/auto-review/summary.json`。

软件验证中，80 项自动化测试通过，覆盖权限和知识库隔离、发布与撤回、引用校验、公式条件及数学判分。生产构建、数据库迁移一致性检查、浏览器操作和移动端布局检查通过。详细记录见 `validation.md`。

本机发现并实测了 BGE-M3、Nomic Embed Text 和 Qwen3 Embedding 三种向量模型。两个演示应用此前分别完成 1024 维和 768 维实际检索验证；本次清空旧知识后暂时下架，配置仍保留。当前已配置 ds-flash，并完成真实语义切分与图文审核调用；问答质量对比仍需独立实验。此前演示回答仅为证据展示，不计入生成式问答实验。

## 5. 实验方案与待补结果

问答对比包括直接调用模型、纯向量 RAG、加入文档定位的混合检索和 GraphRAG，统一生成模型、资料范围和证据预算。实验脚本保留真正的纯向量分支，检索组统一最多 8 个单元、每单元 2,500 字符；线上文档概览的较大预算需另行评估。混合检索与 GraphRAG 对比用于隔离图扩展的影响。统计人工核验的回答正确率、引用支持率、证据召回、拒答精确率与召回率、耗时及 Token 用量。

原研究方案包含 240 个问答样本及 100 个抽取片段。当前只准备了真实片段与问答标注槽位，尚未完成正式标注。短期交付先进行明确标注为预实验的小规模验证。开发集与测试集按原题家族分离，测试答案不用于调整提示词和权重。

| 待补项目 | 当前状态 |
|---|---|
| 真实生成模型、服务及参数 | 已配置 ds-flash；切分及视觉审核已验证 |
| 人工审核的教材知识与评测集 | 待完成 |
| 三组问答对比及失败案例 | 待运行和人工评分 |
| 重要性排序 NDCG@10 | 待独立人工重点清单 |
| 加入前置关系的推荐效果 | 待独立薄弱点标注或实际参与者 |

在上述工作完成前，不声明达到 95% 引用支持率、90% 计算题正确率，也不宣称 GraphRAG 已优于纯向量检索。功能测试的通过率不能代替问答质量指标。

## 6. 当前结论与局限

已构建并部署多应用学习平台，验证了知识范围隔离、来源定位、版本发布与限定数学判分等软件行为。真实 Embedding 检索可运行，真实教材已导入，可编辑后直接发布。

教材内容完善和质量实验是当前主要未完成工作。扫描 PDF 与图片已接入 PaddleOCR-VL-1.6 云端识别，支持公式 LaTeX、表格内容及原图校对；ds-flash 图像审核已接入并完成本批资料处理，手写公式和复杂图形语义理解尚未完成系统评价。知识溯源说明信息出处，无法自行保证教材或回答正确；学习效果也需要真实学生与适当实验设计支持。
