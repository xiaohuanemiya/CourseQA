# CourseQA 使用与运维说明

[返回项目首页](../README.md)。首次克隆、容器启动及本地开发命令见首页；本文说明应用行为与配置边界。文中的路径和命令均以仓库根目录为基准。

## 资料与应用发布

1. 在“模型与连接”添加生成和 Embedding 配置，执行连接测试。
2. 创建知识库，为需要模型语义切分的资料选择生成模型。上传支持 PDF、图片、DOCX、PPTX、TXT、Markdown，每份默认最大 30 MB。
3. 编辑知识、公式、条件、来源和题目；可对照原图修正识别内容，相似条目由管理员决定是否合并。
4. 发布知识库：构建有效条目的快照以及应用所需的向量索引，成功后切换当前版本。
5. 在“应用管理”选择生成模型、Embedding 模型和知识库，设置问答/自测功能及提示词，保存草稿并发布。
6. 学生登录后问答、自测；管理员在“复习计划”和“图数据库”查看学习记录、错题及知识关系。

流程为 **上传 → OCR 或文字解析 → 切分 → 入库 → 按需生成关系 → 发布知识库 → 发布应用**。内容保存后可直接发布，没有人工或模型审核关卡；来源范围、关系循环、数学参考答案、向量维度及权限仍由程序校验。

编辑进入草稿，不修改当前发布正文。撤回立即影响新检索；生成中的回答保存前再次校验应用版本、知识版本及撤回状态。生成或索引构建失败时保留原发布版本。

每个应用独立选择生成和 Embedding 配置。同一知识版本可以保留多个向量索引；更换 Embedding 时先构建新索引再发布。已发布应用引用的模型配置不能原地修改服务地址、型号或维度，应复制配置再切换；更新 API 密钥无需重建向量索引。

### 批量上传与重新处理

在知识库列表或详情页点击“上传资料”，选好页码、切分方式及模型后选择多个文件或拖入。每个文件保留选取时的设置；随后改表单不会影响已排队文件。队列逐个提交，收到后台任务编号后继续下一份，无须等解析完成。

单个失败不影响其他文件。“重试上传”只重传对应文件，“重试处理”复用原任务，不创建新文档版本。相同内容由后端阻止重复导入。当前标签页保存已提交任务的跟踪信息；本地待上传文件不存入浏览器存储，未确认上传的文件需重新选择。清除队列记录不会删除资料。

按新参数重新解析已有文件会产生独立文档版本，不改写原文件。整理新版本、撤回不用的旧内容，再发布知识库，学习应用才会使用新的发布内容。

## 模型与 OCR

OpenAI 兼容接口填写完整 API 基础地址；通常包含 `/v1`，具体以所用服务为准。Ollama 填写服务地址，可在管理端扫描其模型。接口连接测试不保证模型支持 Tool Use；启用 Agent 前需选择支持原生工具调用的模型。Skill、模型文件和平台工具是不同层次的能力。

应用问答不设置输出 Token 上限，不裁剪完整回答或已保存的对话。OpenAI 兼容请求省略 `max_tokens`，Ollama 使用 `num_predict=-1`；模型服务自身仍有输出和上下文限制，报告截断时拒绝保存残缺回答。输入上下文、工具预算和文档切分任务另有明确上限。

PDF 与图片始终使用配置的 **PaddleOCR-VL-1.6 云端异步服务**。在本地 `.env` 设置 `PADDLEOCR_TOKEN`，需要时调整 `PADDLEOCR_MODEL`、`PADDLEOCR_JOB_URL`、`OCR_TIMEOUT`，随后重新创建 API/Worker 容器使环境变量生效。Token 不返回前端或写入识别报告。

PDF 起止页在本地截取后上传，长文按 20 页分批识别并缓存已完成批次；失败重试会查询原云端任务。保留原页码、公式、表格、图片区域和识别位置，管理员可在“识别校对”中对照原图编辑。识别输出和文字覆盖率不能证明数学正确性。

`OCR_ENABLED=false` 会禁止 PDF/图片导入，不能绕过为 PDF 文字层读取。完全本地体验可使用 TXT、Markdown、DOCX、PPTX 的文字内容并配置本地生成与 Embedding 模型；Office 内嵌图片和公式若需 OCR，应先导出为 PDF。服务失败不会自动发送给其他服务。

## 文档切分与知识关系

| 切分方法 | 处理方式 | 是否调用生成模型 |
|---|---|---|
| 整篇文档 | 一篇作为一个单元，最多 30,000 字符 / 256 个来源块 | 否 |
| 按页 / 幻灯片 | 按真实页码聚合，无稳定页码时拒绝使用 | 否 |
| 按段落 / OCR 内容块 | 在公式块以外按段落划分 | 否 |
| 固定字符 | 配置长度与重叠，可能截断公式 | 否 |
| 递归文本 | 优先空行、换行、句号等边界，保留可识别的数学环境 | 否 |
| 模型语义切分 | 模型选择连续原文块的分组、标题与知识类型 | 是，使用所选生成配置 |

语义切分只让模型返回边界与标注，正文、公式、来源页码和图片由原文重建；不允许模型改写正文或编造来源。最长请求窗口为 16,000 字符 / 96 个单元，保留窗口末组以支持跨页整合。程序校验顺序、覆盖、重复及长度，失败最多重试三次，不能得到完整合法分组时明确失败。

切分缓存按原文、参数、模型与算法版本隔离；仅改切分方式不重新调用 OCR。切分报告显示实际模型、块数、条目数与原文覆盖率，规则切分标注为“未进行模型语义提取”。DeepSeek 官方接口的切分调用使用非思考模式；其他兼容服务不发送该专用字段，问答模型参数不因此改变。

上传接口的 multipart `splitting` JSON 与重新处理的 `ParseOptions.splitting` 使用 `method`、`chunk_size`、`overlap`、`model_profile_id` 等字段。可通过 `GET /api/admin/splitting-methods` 和 `GET /api/admin/documents/{id}/splitting` 查看支持的方法与报告。

### 图谱与关系生成

管理员从“图数据库”进入 `/admin/graph`，可按知识库查看草稿/发布图谱，筛选节点和关系，查看邻域、路径、来源及向量索引信息，导出当前视图。课程知识关系与文档溯源分别展示；该界面不开放任意 SQL/Cypher。

在“知识库 → 知识关系”选择真实生成模型，按需生成前置、使用定理、使用公式、考查、易混淆和相关关系。该操作独立于 OCR 与切分，已有资料无须重新导入。

每批最多 8 条主体知识，另选最多 8 条正文相关候选。模型给出关系、理由及两端原文摘录，程序检查同库 ID、类型方向、摘录、自环、重复和前置循环。候选不是所有知识对的穷举，摘录匹配也不证明语义关系必然正确；管理员可以查看、修改或撤回。

关系在整个任务成功后一次保存，失败不留下半批数据；重试可复用已完成批次，资料在执行期间变化则拒绝保存过时结果。不复活已撤回关系，不自动发布。接口为 `GET/POST /api/admin/knowledge-bases/{id}/relation-generation`，POST 可指定 `model_profile_id`。

## 检索、比较与多轮追问

检索限于应用绑定知识库的有效发布内容。文件名、年份、课程与考试类型用于定位指定资料；单个对象不存在或仍含糊时要求补充条件，不用其他年份或课程替代。

明确比较时可指定 **2～3 个对象**，例如“比较《2024年期中试卷.pdf》和《2025年期中试卷.pdf》的考点”。逐个定位后按资料组均衡选择证据；题卷与配套答案保留各自归属。任一目标缺失、含糊或指向同一组资料时先澄清，超过 3 个对象需分批。

- 普通知识问答：BM25 与向量候选融合，再按有效知识关系扩展，最多 8 个单元。
- 文档概览：按章节/页面收集正文，过滤纯标题、考生信息和页码，最多 32 个单元、24,000 个正文字符。
- Agent 追加检索：合计最多 48 个单元、48,000 个正文字符。

上述预算约束输入，不限制输出长度。概览优先试题正文，询问答案时优先答案文件；证据不完整时必须说明覆盖局限。结果的 `retrieval` 记录策略、匹配文档及覆盖情况，引用附带文件、版本、页码或定位信息。

同一会话带入经过权限、版本与引用检查的近期问答，最多 6 轮、8,000 字符；更早用户问题提供可追溯的摘录摘要，最多 8 项、2,000 字符。历史用于理解指代和题目条件，不能作为新证据，历史引用编号不会沿用。

追问的历史主题只辅助排序，资料范围只用于指代；意图由**当前问题**判断。例如先问“总结这份试卷”，再问“第 2 题如何求导”，不会因旧问题中的“总结”继续概览整篇。本轮明确给出新文件或年份时优先使用新目标；独立提问不继承旧范围。应用、发布或引用已变化的历史内容不进入本轮提示。

### 引用与原文对应

`answered` 必须包含非空正文和有效的正文 `[编号]`。`citation_ids` 只接受不重复的有效编号字符串，并须与正文实际引用一致；单独列出参考资料不能满足该要求。数学环境、代码及 Markdown 链接中的数字方括号不计为引用。

模型可提供 `supports=[{claim,citation_id,quote}]`：程序检查 `claim` 确实出现在正文，`quote` 是对应证据正文的连续摘录，只允许规范化空白。最多 32 项，结论和摘录各不超过 2,000 / 4,000 字符，总计不超过 32,000 字符。错误或伪造映射拒绝保存；旧模型没有该字段时兼容，但不标记为已核对原文对应。

页面可展开结论与摘录；`support_validation` 明确说明这是文本对应检查，**不是语义蕴含证明**。原文是否真正支持结论仍需人工评价，系统不承诺零幻觉，也不为该检查额外调用模型。

## 自主 Agent、Skills 与 Tool Use

在应用设置中启用“自主学习助教”，保存并发布。新建应用的管理界面默认启用；已有配置或未传 `agent` 的 API 请求保持原问答模式。演示模型只展示证据。

模型在同一流式循环中决定直接回答、读取 Skill、检索、计算或拆出子任务。简单问题可一次调用直接回答；子 agent 使用同一生成模型与独立上下文，不能递归创建子 agent。父子任务共享全局引用编号，最终结果仍经过引用和版本检查。

| 工具 | 作用 |
|---|---|
| `search_knowledge` | 补充检索当前应用已发布知识，继承已确认的文档范围 |
| `read_skill` | 按需读取启用 Skill 的完整方法 |
| `read_skill_reference` | 读取对应 Skill 的 `references/*.md` |
| `calculate` | 使用受限数学工具求导、积分、极限 |
| `spawn_agent` | 创建独立子任务，将报告交回主 agent |

| Skill | 用途与支持范围 |
|---|---|
| `course-evidence` | 课程概念、条件与原文证据检索 |
| `calculus-verification` | 微积分表达式、定义域与工具计算核验 |
| `document-comparison` | 讲义、试卷概览和对比，保留文档归属 |
| `sympy` | 符号数学方法参考；平台工具仅执行求导、积分、极限 |
| `scientific-critical-thinking` | 科学证据、偏差与推理方法；不提供外部文献或示意图服务 |

前三个 Skill 为本项目编写，后两个导入自 K-Dense 科学技能库。完整来源、提交、校验值与许可分别见 [imports.json](../backend/app/skills/imports.json)、[THIRD_PARTY_LICENSE.md](../backend/app/skills/THIRD_PARTY_LICENSE.md)。

Skill 是方法说明，不是课程事实来源。原文中的 Python、Bash、安装命令和外部服务示例不授予执行权限；平台只执行上表工具。数学工具使用受限 AST 和独立进程，不接受任意代码，不对学生输入使用 `eval` 或 `parse_expr`。

### 扩展与发布技能

将经检查的技能包放到 `backend/app/skills/<name>/SKILL.md`，包含 YAML `name`、`description`，名称与目录一致；参考文件放在 `references/`。可用 `requirements` 声明工具依赖，在 `backend/app/skills/runtime.json` 声明平台适配及限制。缺工具或未经适配的外部工具声明不能直接启用。

重建后在应用设置选择并发布。每次发布固定正文、参考资料、适配声明与哈希；更新镜像中的文件不会改变已发布版本。旧发布无快照时，每次运行捕获一致的临时版本并记录 `legacy_live`，重新发布后固定。新增 Skill 不会自动获得新的工具能力。

### 预算、过程与诊断

默认最多 3 个子 agent、同时执行 2 个，主 agent 最多 6 个工具轮次，父子合计最多 24 次工具调用，整个 Agent 回答超时 180 秒。子 agent 轮次为主上限与 4 的较小值；管理员可在应用配置调整。到达轮次/次数上限后允许一次禁用工具的收尾回答，并记录限制。

参数、权限、依赖、预算与服务错误有具体错误码。尚未输出内容的暂时连接/服务错误最多自动重试一次。超时、版本变化、资料撤回或无效引用不会保存成功回答。

“查看学习过程”展示 Skill、工具与子任务进度、耗时、模型调用数、Token 用量；未报告用量时显示“未提供”。成功记录保存 Skill 哈希与计算结果，不保存或展示模型私有推理。失败通过 `agent_failure` 写入审计，仅包含诊断信息，不保存失败正文或原始参数。管理员接口为 `GET /api/admin/audit/{app_id}`、`GET /api/admin/agent-capabilities`。

## 流式回答、去重与取消

`POST /api/apps/{id}/chat/stream` 返回 SSE，普通 `POST /api/apps/{id}/chat` 返回 JSON。SSE 包含 `request`、`status`、`agent`、`delta`、`reset`、`error`、`done`：`request` 给出请求编号，`reset` 清空临时正文，`done` 给出完整已保存结果。每 10 秒发送连接心跳，Nginx 关闭缓冲；正文使用有界缓冲，慢客户端会暂停上游消费。

客户端为每次新问题生成 UUID 字符串 `request_id`，恢复连接时沿用原编号与参数；旧客户端未传编号时由服务端生成。相同用户、应用、编号和参数最多执行一次：处理中重复请求等待已有执行，完成后复用原结果与会话，不重复调用模型或写消息。相同编号但参数不同返回 409。

`failed`、`cancelled` 和租约过期的请求不以同编号重跑；重新提问须用新编号。成功 SSE 重放只发送 `done`，失败/取消重放返回 409（SSE 为 `error`）。

| 接口 | 行为 |
|---|---|
| `GET /api/apps/{id}/chat/requests/{request_id}` | 查询本人的请求 `state`、`result`、`error` |
| `POST /api/apps/{id}/chat/requests/{request_id}/cancel` | 持久取消排队中/运行中的请求，已成功请求保持成功 |

状态为 `queued`、`running`、`succeeded`、`failed`、`cancelled`。消息与成功请求记录在同一事务保存；即使错过最后一个 `done` 也可查询已保存结果。查询与重放重新检查应用版本、资料版本和撤回，已过时结果返回 `status=outdated`，隐藏旧正文与引用。

前端网络异常时查询已有请求，无法立即确认时可点击“检查这次回答”；不会恢复尚未完成的模型输出。停止或离开页面取消未完成请求，残缺预览不会保存为成功回答。异步模型请求可取消；同步请求排队时可取消，已发出的同步 HTTP 请求需等待线程返回后清理，已取消请求不能提交成功结果。

## 缓存与并发配置

**检索缓存**是进程内有界 LRU：复用 BM25 词项统计与图拓扑，最多 24 项、估算总权重 8 MB。键包含应用/发布范围、当前有效正文与关系指纹，撤回或内容变化后重新构建；不缓存用户问题、对话、回答、权限判断、数据库会话或跨请求查询向量。

**工具复用**只限同一次 Agent 执行：相同参数的检索、技能读取及成功计算可共享结果，相同并发请求等待同一次执行；复用前仍核对版本。失败或未完成计算不缓存，子 agent 创建不复用。每次工具请求仍计入预算，`tool_executions` 与 `cache_hits` 分别记录实际执行及复用。

**问答限流**使用共享数据库租约，协调多个 API worker。用户额度跨该用户应用合计；模型额度按配置 ID 分组，涵盖问答内生成、Embedding 及主子 agent 请求。复制模型配置会形成另一组额度。该机制不自动覆盖后台导入、关系生成或独立评测脚本。

| 环境变量 | 默认值 | 含义 |
|---|---:|---|
| `MODEL_CONCURRENCY` | 4 | 每模型配置同时调用数 |
| `MODEL_QUEUE_CAPACITY` | 24 | 每模型配置等待数 |
| `MODEL_QUEUE_TIMEOUT` | 30 | 模型排队最长秒数 |
| `USER_CHAT_CONCURRENCY` | 2 | 每用户同时问答数 |
| `USER_CHAT_QUEUE_CAPACITY` | 4 | 每用户等待问答数 |
| `USER_CHAT_QUEUE_TIMEOUT` | 30 | 用户排队最长秒数 |
| `ADMISSION_LEASE_SECONDS` | 30 | 租约时长，由执行者续期 |
| `ADMISSION_POLL_SECONDS` | 0.2 | 排队轮询间隔 |

队列满或等待超时明确失败，取消和异常释放资源，进程退出后通过租约过期回收。配置示例见 [.env.example](../.env.example)。升级数据库执行 `alembic upgrade head`；Podman 启动/重建脚本已在服务启动前执行迁移。部署数据库与文件卷应一并备份。

## 自测、权限与验证

题库绑定知识点，支持难度、章节筛选和参数化模板；题量按实际可用数量显示，同一道题只计一次作答。表达式判分区分非等价、定义域差异、积分常数和不确定结果，证明题不自动判分。管理员可查看复习建议、掌握程度及错题；学习页面不加载管理端图谱或复习数据。

API 使用 HttpOnly 会话 Cookie；修改请求需 `X-Requested-With: calculus-studio`。会话/作答按用户和应用隔离，资料访问由服务端按发布绑定校验，客户端不能自行提交其他知识库绕过范围。

自动化测试覆盖隔离、发布与撤回、模型协议、取消/并发、工具复用和引用校验。浏览器专项脚本如 `scripts/browser_agents.py` 使用临时数据库与本地模型替身；`scripts/browser_smoke.py` 检查已有 Podman 部署，要求特定模型并写入聊天/作答记录，不能作为任意新部署的通用验收。运行前核对 [脚本说明](../scripts/README.md)。模拟响应不代表真实模型质量或速度。

真实课程质量评测见 [实验与数据标注](../evaluation/README.md)。`scripts/evaluate_agents.py prepare/run/score` 比较普通问答、工具模式和多 agent；候选须人工审核，真实 `run` 会调用应用配置的模型。没有真实模型、已审核问题与人工评分时，不生成准确率、引用支持率或学习效果结论。历史检查结果保留在 [验证记录](validation.md)，不作为新部署的当前状态。
